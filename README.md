# ことばね

AIが作成した日本語の下書きに見られる定型句や反復を検出し、意味・主張・出典を保ちながら自然な文章へ整えるワークスペースです。下書きを貼り付けて「AI文体をチェック」を押すと、該当箇所と理由を確認できます。「書き換え案を作る」と検出箇所を手掛かりに推敲し、原文との違いと文体特徴スコアを表示します。詳しい文長や語彙は「文章の統計」から確認できます。React、TypeScript、Tailwind CSS、Vite と Node.js の同一オリジン API を使用します。

## 起動方法

Node.js 22.13 以上と npm を用意し、この README があるフォルダーで実行します。

```sh
npm ci
npm run dev
```

表示されたローカル URL をブラウザーで開きます。初期画面では大学レポートのサンプルを確認できます。統計、ハイライト、履歴、文体プロファイル、ファイル入出力には API キーが不要です。

PWA は本番ビルドで動作します。

```sh
npm run build
npm start
```

既定の URL は `http://127.0.0.1:4173` です。PC ではブラウザーのインストール機能を使います。iPad では HTTPS URL を Safari で開き、共有メニューの「ホーム画面に追加」を使います。初回オンラインでキャッシュが完了した後は、アプリ画面・分析・端末内履歴などをオフラインで利用できます。AI リライトには接続が必要です。PDF の一部では、未キャッシュのフォントや CMap の取得が必要になることがあります。

PC と iPad で同じサーバーを利用する場合は、信頼できる HTTPS リバースプロキシの背後で本番サーバーを実行してください。以下の設定は接続構成に合わせて指定します。プロキシからはブラウザーが使用したホスト名をそのまま渡してください。

- `PORT` は Node サーバーのポートです。既定値は `4173` です。
- `HOST` の既定値は `127.0.0.1` です。外部アドレスを指定する場合は、`APP_USERNAME` と `APP_PASSWORD` の両方が必要です。開発サーバーはローカル確認用です。
- アプリの履歴とプロファイルはブラウザーとオリジンごとに保存されます。

## API 設定

`.env.example` を同じ場所の `.env` にコピーします。PowerShell では `Copy-Item .env.example .env` を実行します。次のうち使うサービスのキーとモデル ID を設定し、起動中ならサーバーを再起動します。

| 変数 | 設定内容 |
| --- | --- |
| `GEMINI_API_KEY` | Google AI Studio で発行したキー |
| `GEMINI_MODEL` | GenerateContent と JSON Schema 構造化出力に対応するモデル ID |
| `OPENAI_API_KEY` | OpenAI API のキー |
| `OPENAI_MODEL` | Responses API と JSON Schema 構造化出力に対応するモデル ID |

アプリの「AIサービス」で Gemini と OpenAI を選択できます。キーは Node.js のサーバー側からのみ読み込みます。設定ファイルを共有せず、クライアント公開用の `VITE_` 変数にはキーを設定しないでください。

「書き換え案を作る」を押すと、対象の原文、前後の文脈各最大1,000 UTF-16コード単位、対象範囲の修正候補最大24件、設定、指定用語、選んだ文体プロファイルの集計値が選択先に送信されます。履歴はブラウザーの LocalStorage に最大40件保存します。自作文サンプルの原文はプロファイルには保存されません。文体チェックやファイル抽出は端末内で処理します。 [Gemini 構造化出力](https://ai.google.dev/gemini-api/docs/structured-output) · [OpenAI Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)

## 実装済み機能

| 段階 | 実装 |
| --- | --- |
| 1 | 原稿入力、文字数・文数・段落数、平均文長と標準偏差、文長分布、語彙の多様度、頻出語、接続詞、文末表現、段落長 |
| 2 | 文体特徴スコア、項目別のグラフ、原文ハイライトと理由表示 |
| 3 | Gemini／OpenAI 切り替え、全文・選択範囲のリライト、文体・目標文字数・変更度・維持する用語の指定 |
| 4 | PDF・Word・テキスト読み込み、並列／差分表示、自動照合、AI による比較、再分析、履歴、コピー・Word・テキスト出力 |
| 5 | 自作文2本以上からの文体プロファイル作成、リライトへの適用、特徴ラベルと文字範囲の回帰検証 |

入力は20,000 Unicodeコードポイントまで、ファイルは15 MBまでです。PDF は100ページまでのテキスト層付き文書、Word は `.docx`、テキストは `.txt`（UTF-8・BOM付き UTF-16・Shift_JIS）に対応します。縦書き、段組、罫線付き表などは抽出順が原稿と異なる場合があります。Word の書式は引き継がず、出力は本文の段落を使った新規文書です。

### スコアと整合性チェック

AI文体特徴スコアは、定型表現38%、文頭の接続詞の多用・反復24%、連続して同じ文末23%、文長の特徴10%、長い段落5%の加重集計です。各項目は0～100に丸めます。接続詞は同じ語が複数回現れるか、2文以上のうち40%以上が接続詞から始まる場合に検出します。文長は70字超の文の割合と文長のばらつきを、段落は300字以上の段落の割合を使います。語彙は `Intl.Segmenter('ja')` で分割します。文や段落の境界は句読点と改行から推定するため、見出しや箇条書き、略記の多い文書では実際の構造とずれることがあります。同じ特徴は人の文章にも現れます。スコアは執筆者の特定や不正行為の判断には使えません。

リライト後は数値・日付、引用符で囲まれた文言、対応する形式の出典表記、指定用語を原文と照合します。内容・主張などはリライトを生成した AI の自己レビューを表示します。意味の維持をプロンプトで優先するため、文字数は目標として扱います。変換案を採用する前に、根拠や結論を原文と確認してください。

## 未実装・検証範囲

- 画像PDFの OCR、旧 Word 形式（`.doc`）、PDF／Word のレイアウトや書式の保存。
- 外部資料による出典の実在確認、文意維持の保証、独立した校閲モデルによるレビュー。
- 端末間の履歴同期と機械学習による追加学習。文体プロファイルは自作文の統計値を使います。
- 大規模な日本語コーパスでの特徴検出性能の評価。現時点では、接続詞や文末反復などの期待箇所を人手で設定した短いサンプルで検証しています。
- Gemini／OpenAI の実キーによるライブ実行。プロバイダー別の構造化応答、エラー、切り替えは模擬レスポンスで検証します。

## テスト

```sh
npm test
npm run build
```

自動テストでは日本語統計、色付けの文字範囲、部分リライトの API 契約とキーの非公開、日本語 PDF の抽出、Word 往復、日本語差分、数値・引用・出典・用語の照合、プロファイル作成を確認します。`npm run build` は TypeScript の型チェック、Vite ビルド、PWA の Service Worker 生成を行います。
